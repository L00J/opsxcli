## 🎯 优化措施

### 1. System Prompt 精简 ✅

**优化前 (~1000 tokens):**
```
你是专业的全栈运维开发和资深运维专家AI助手。

【专业领域限制】
你ONLY处理以下运维相关问题:
✅ 系统运维: Linux/Unix系统管理、性能优化、监控告警
✅ 应用部署: 软件安装、配置管理、服务部署
...
(冗长的列表和说明)
```

**优化后 (~200 tokens):**
```
运维AI助手。专注: 系统运维、容器编排(Docker/K8s)、数据库管理、网络配置、自动化部署。

核心原则:
1. 立即执行,不过度规划
2. 合并相关命令减少调用(如: uptime && free -h && df -h)
3. 失败后分析原因再调整
...
```

**效果:** 每次请求节省 ~800 tokens

### 2. 会话自动压缩优化 ✅

**优化前:**
- 基于消息数量判断 (20条消息)
- 不考虑实际 token 使用

**优化后:**
```go
func (a *Agent) shouldCompact(messages []llm.Message) bool {
    // 基于 token 估算 (更准确)
    estimatedTokens := 0
    for _, msg := range messages {
        estimatedTokens += len(msg.Content) / 2
        for _, tc := range msg.ToolCalls {
            estimatedTokens += len(tc.Function.Arguments) / 2
        }
    }

    // 如果估算超过 15k tokens,触发压缩
    return estimatedTokens > 15000
}
```

**效果:** 更精准的压缩时机,避免 token 线性增长

### 3. 工具调用策略改善 ✅

**优化前流程 (11次调用):**
```
1. uname        → 获取系统信息 (不必要)
2. uptime       → 负载信息
3. top          → 进程信息
4. free         → 内存信息
5. df           → 磁盘信息
6. dd (failed)  → 磁盘写入测试 ❌
7. dd (write)   → 磁盘写入测试
8. dd (read)    → 磁盘读取测试
9. rm           → 清理
10. iostat      → IO 统计
11. loadavg     → 负载详情 (重复)
```

**优化后流程 (6次调用):**
```
1. uptime && free -h && df -h  → ✅ 合并获取负载+内存+磁盘
2. dd 写入+读取+清理 (一条命令)  → ✅ 合并测试(虽然仍失败一次)
3. lsblk && iostat              → ✅ 合并磁盘信息+IO统计
4. iostat 多次采样              → IO等待分析
5. nproc && loadavg && ps       → ✅ 合并CPU+负载+进程
```

**效果:**
- 调用次数减少 45%
- AI 学会了"合并命令"策略
- 减少了不必要的调用 (如 uname, 重复的 loadavg)
