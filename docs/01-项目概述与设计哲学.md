# 01 - 项目概述与设计哲学

> 建议阅读顺序：01 → 02 → 03 → ... → 09

## 🎯 项目定位

**opsxcli** —— 一个智能运维超级助手。

基于 Go + Cobra 构建的 CLI 运维工具集，融合 LLM Agent 能力，让运维操作从「手动执行命令」升级为「自然语言对话式智能运维」。

|------|------|
| Go 文件 | 287 个 |

| 测试覆盖率 | 32.1% |
| LLM Provider | 15 个（注册制） |
| Agent 子包 | 7 个 |
| 命令插件 | 30+ |

## 🏛️ 三层架构

```
┌─────────────────────────────────────────────┐
│              cmd/ 命令行接口层                │
│   Cobra 命令定义、参数解析、用户交互入口       │
├─────────────────────────────────────────────┤
│            plugins/ 功能实现层                │
│   独立插件实现：mysql, ssh, ping, curl ...    │
├─────────────────────────────────────────────┤
│           internal/ 核心引擎层               │
│   agent/    ── Agent 子系统（7 个子包）       │
│   llm/      ── LLM 客户端抽象               │
│   logger/   ── 日志系统                      │
└─────────────────────────────────────────────┘
```

### 各层职责

| 层 | 职责 | 关键特征 |
|----|------|----------|
| **cmd/** | 命令入口 | Cobra 命令定义、参数绑定、帮助文本 |
| **plugins/** | 功能实现 | 独立目录、Go 原生实现、无系统依赖 |
| **internal/agent/** | 智能引擎 | ReAct 循环、工具调用、自我进化 |
| **internal/llm/** | LLM 抽象 | Provider 注册制、统一接口 |

## 🧠 Agent 子系统全景

Agent 子系统是 opsxcli 的智能核心，包含 7 个子包：

```
internal/agent/
├── core/       ── 核心引擎：16 轮 ReAct 主循环 + 自适应检查点
├── prompt/     ── Prompt 构建：五层 System Prompt + 动态记忆注入
├── evolver/    ── 自进化引擎：三层记忆 + 经验学习
├── safety/     ── 安全系统：风险评估 + 三级安全模式 + 审计
├── session/    ── 会话管理：JSONL 持久化 + 导出
├── tools/      ── 工具注册：Tool 接口 + Registry + SSH 连接池
└── tui/        ── 终端界面：Bubble Tea TUI + Markdown 渲染
```

## 💡 四大设计哲学

### 1. 安全第一 (Safety First)

> 运维工具的底线是「不搞砸」。

- 所有工具执行前必须通过安全评估
- 三级安全模式：strict / balanced / permissive
- 5 级风险等级：Safe → Low → Medium → High → Critical
- 危险命令黑名单 + 动态风险评估
- 完整审计日志记录每一次工具调用

### 2. 渐进式复杂度 (Progressive Complexity)

> 简单任务零配置，复杂任务有能力。

- 默认配置即可运行（NewDefaultConfig）
- 环境变量覆盖机制（LoadConfig）
- Agent 初始化时优雅降级（Evolver 失败不阻塞）
- 安全模式按需升级（balanced 默认 → strict 高敏环境）

### 3. 工具化思维 (Tool-Oriented)

> 万物皆 Tool，一切可注册。

- 统一的 `Tool` 接口：Name / Description / Parameters / RiskLevel / Execute
- `Registry` 线程安全注册中心
- 实现接口即可扩展，无需修改核心代码
- 内置工具：local_bash, ssh_execute, scp_transfer, file_read, file_search, analyze_output

### 4. 自我进化 (Self-Evolution)

> 用得越多，越懂你。

- Evolver 引擎在任务完成后自动学习
- 三层记忆：经验记忆 / 环境记忆 / 用户偏好
- 经验按成功率排序，高成功率经验优先注入 Prompt
- 用户偏好自动积累（常用路径、服务器信息）

## 🔌 LLM Provider 注册制

Provider 采用工厂注册制，`factory.go` + `init()` 自注册：

```go
// 注册新 Provider 只需两步：
// 1. 实现 llm.Client 接口
// 2. init() 中调用 RegisterProvider()

func init() {
    RegisterProvider("mymodel", NewMyProvider)
}
```

已注册的 15 个 Provider 覆盖国内外主流模型，包括 GLM（智谱）、DeepSeek、MiniMax 等。
